```text
┌──────────────────────────────┐
│ ‹                            │
│ [       参考图预览       ]    │
│                              │
│ 眼前是什么让你停了下来？      │
│                              │
│ [ 按住说一句话…… ]            │
│                              │
│ 一束光   一个形状   色彩关系   │
│ 空间层次  某个细节   说不清    │
│                              │
│ 现场机位可以怎样调整？         │
│ □ 前后  □ 左右  □ 改变高度    │
│ 未选择的方向按原位置附近处理   │
│                              │
│ ▸ 补充更多现场信息（可选）     │
│   画面里有什么 / 现场环境       │
│   想保留什么 / 愿意弱化什么     │
│                              │
│             [ 看看可能性 ]    │
└──────────────────────────────┘
```

提交后先显示“正在看清画面”的阶段状态。若关键不确定性会改变关注对象或取舍，原位显示一个澄清问题和 2～3 个候选答案，保留已选图片及全部输入；用户回答后继续分析。

结果页只在至少两种方向成立时以两列卡片展示 2～5 个不排名方向，第 3～5 个必须包含新关系或新取舍；不足两种时改为展示“没有足够可靠的观看方案”、原因、已检查依据和可选下一步，不显示空方向卡片。每张方向卡片首先显示浏览器本地裁切并放大的取景预览：优先采用 `suggested_crop`；缺失时依据 `view_width`、画幅方向和已有关注区域做确定性范围模拟，并标记“视角范围模拟”。卡片随后点名至少两个具体画面元素及其关系，并露出第一条“现场先这样试”。方向详情并排显示范围预览和“完整原图中的位置”，再展示机位关系、完整 2～3 步及对应观察信号。预览必须说明它只模拟取景范围，不代表机位、透视、光线或最终成片。结果末尾提供本地反馈，不上传图片或输入文字。


## 设计验证重点

- 用户是否理解建议没有排名。
- 用户是否能找到“怎么拍”，但不会过早被参数吸引。
- “保留/可以减少”是否比构图术语更容易理解。
- 用户是否能理解机位关系是相对参考图的试拍方向，而不是精确导航。
- 模型不确定与 Mock 未识图状态是否足够醒目。
- 一只手持手机时能否完成主要操作。
