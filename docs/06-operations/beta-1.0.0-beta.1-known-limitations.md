# `1.0.0-beta.1` 已知限制

最后更新：2026-07-28

本版本是“照见 1.0 Skill 基础版”的工程 Beta。它用于受限验证版本化摄影 Skill、自动训练、个人创作记忆和可追溯创作意图，不等同于已经完成商店、备案、支付、真实设备矩阵和公开运营准备的商业发布。

## 部署边界

- 当前只支持单实例：SQLite 主数据库、进程内任务队列、内存额度与频率限制、SQLite Blob 分析图存储。
- 不得把当前部署描述为多实例就绪。扩展前仍需要 PostgreSQL、Redis、对象存储、持久化任务队列和共享 Data Protection 密钥。
- 进程重启可从数据库恢复未完成任务；多个实例同时运行仍不具备分布式额度、频率限制和任务调度一致性保证。
- 密码恢复邮件尚未配置时，只允许显式开启的 loopback 开发恢复码；公开环境不能使用这条演示路径。

## 模型、成本与评测

- 默认开发与 CI 使用 Mock，不读取图片内容，也不会访问模型或产生费用。
- 真实分析和训练依赖外部视觉模型；超时、限流、区域服务或供应商策略变化仍可能让云端分析不可用。
- `1.0.0-beta.1` 的工程发布证据只有在固定 60 图真实模型运行、九维门禁、成本、延迟、失败调用和隔离样例均已归档后才可标记为 `ready`。3 图烟测不能替代该门槛。
- 真实运行最多接受 15 个可追溯的受控修复调用，其中最多 1 个缺少可信用量的上游调用按最坏单次租约计费；每个失败或不确定尝试都必须由同资产、同角色的下一次成功尝试闭合。未闭合调用、失败/取消样例或第 2 个不确定调用都会阻断发布。
- 费用字段是依据 Token 与冻结计价快照得到的可追溯估算，不是供应商账单或用户扣款凭证。
- 同模型不同角色会明确记录为 `same_model_different_roles`，不能冒充不同模型家族的独立交叉验证。

## 个人创作记忆

- 个人创作记忆默认关闭；只有用户明确开启记忆并同意同步枚举反馈后，当前账号的白名单字段才会上传。
- 单次点击、停留时间、完整标题、用户原话、图片、GPS、设备序列号和模型内部推理不会形成稳定偏好。
- 至少两个不同分析任务的明确反馈才可能形成结构化偏好；用户可以停用、修改、删除或全部清空。
- 去标识化全局候选与活动 Skill 物理隔离，运行时没有读取候选表的入口。Beta 不承诺已经积累足够数据形成首个全局自动升级。

## CreativeIntent 与后期能力

- `CreativeIntent` 保存来源分析、选中方向、Skill 版本和摄影包快照，用于摄影日记与未来复盘。
- `FinalPhotoObservation` 和 `PostProcessPlan` 目前只是契约草案，只描述可见事实、多个可逆思路、依据、预期变化、取舍和不确定性。
- 本版本不解码 RAW，不生成 Lightroom/XMP，不执行曲线、HSL、蒙版或像素修改，不覆盖原图，也不提供唯一正确后期答案。

## 图片与数据

- 服务端只保存浏览器重新编码并去除元数据的 JPEG 分析图，不保存原图、完整 EXIF 或精确 GPS。
- 分析图默认保留 30 天；到期后保留结构化结果，历史页会明确显示图片已清理。
- 账号导出是在线 ZIP，超出当前条数或字节上限时会拒绝并提示维护者处理，不是无限规模归档系统。
- 数据库备份、供应商数据保留设置、客服工单和未来对象存储中的同步删除时限仍需在公开发布前逐项复核。

## 体验与公开发布

- 当前验证面是移动 Web，不包含原生 iOS/Android 相机、相册权限和系统后台生命周期实现。
- 户外强光、单手操作、动态字体、低端/中端/高端真实设备、弱网、磁盘不足与系统回收仍需公开测试前完成人工设备记录。
- 应用备案、网站备案、生成式 AI 相关义务、商标、商店隐私标签、隐私政策、支付退款、审核账号、客服和发布后值守仍以[发布检查表](launch-checklist.md)为准。
- 工程 Beta 报告不能替代公开发布的法律、商店、设备和运营 Go/No-Go。
