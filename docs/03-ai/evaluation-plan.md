# AI 评测计划

## 原则

“构图是否好看”没有唯一标准，因此不设置审美总分，也不让训练模型给自己的输出颁发“有启发”结论。

照见 1.0 的评测分为两层：

- Beta 发布：事实、结构、方向差异、安全边界、跨角色分歧、成本和延迟，由确定性程序与独立模型角色检查。
- 稳定版校准：只使用真实产品中自然产生的选择、修改、拒绝、枚举反馈和摄影日记信号判断是否真正有帮助。

V1 不建立摄影师逐张标注或审核全部图片的离线团队。模型生成的训练结果统一标记为 `model-suggested`，不能冒充人工事实或唯一答案。

## 第一阶段评测集

第一版准备 60 张来源明确的真实摄影图片，另保留仓库中现有 12 个合成固定场景。真实图片按 36/12/12 固定为训练、回归和保留集，覆盖：

- 25 张风光与自然：山地、湖泊、海岸、森林、运动与尺度。
- 15 张城市与日常环境：街道、建筑、桥梁、夜景、遮挡与线条。
- 10 张人物与环境人物：人物和空间、背景、尺度、姿态与光线关系。
- 10 张普通、模糊或困难照片：元素稀少、复杂杂乱、不确定与 `no_options`。

每个样例包含：

- 来源、作者、许可、许可链接、允许用途、署名与内容哈希。
- 去除不必要 EXIF/GPS 后的模型输入图。
- 一个或多个版本化测试意图与摄影包摘要。
- 观察者产生的可见事实、不确定性与证据。
- 批评者和红队检查者发现的问题。
- 明确禁止的虚构、身份推断、危险机位和裁判语言。
- 模型角色提出但不要求候选 Skill 逐字复现的参考方向。
- 模型、角色、提示词、Schema、Skill 和数据集版本。

图片本体不进入 Git；没有明确许可、来源或允许用途的图片不进入训练目录。

## 指标

| 指标 | 定义 | 1.0 Beta 目标 |
|---|---|---:|
| JSON 可解析率 | 返回符合 Schema 的比例 | ≥ 99.5% |
| 严重虚构率 | 编造主要物体、光源或场景的比例 | < 3% |
| 意图响应率 | 建议确实回应用户原话 | ≥ 90% |
| 方向差异率 | 返回的 2～5 项均具有真实取舍差异；不足两项时应返回 `no_options`，不得凑数 | ≥ 85% |
| 画面落地率 | 每个方向至少点名 2 个可核验元素，并准确说明可见关系 | ≥ 95% |
| 澄清有效率 | 提问确实针对会改变关注对象或取舍的不确定性，且回答后不重复提问 | ≥ 90% |
| 现场可执行率 | 每项至少 2 步同时包含动作与可观察结果，且不越过机位自由度 | ≥ 95% |
| 器材可行率 | 建议视角可由器材实现或明确降级 | ≥ 95% |
| 裁判式语言率 | 出现评分、最佳或命令式表达 | < 1% |
| 至少一项被采用比例 | 一次真实分析中至少一个方向被选择、修改或保存；不作为审美分 | Beta 建立基线，稳定版前冻结阈值 |
| 方向值得试比例 | 用户自然标记“值得试一次”的方向占比；按视觉策略分组观察，不合成审美分 | Beta 建立基线，稳定版前冻结阈值 |
| P95 延迟 | 从提交到可渲染结果 | 待原型测量 |
| 单次分析成本 | 画面理解、方向生成、可选修复、存储和网络合计 | 待原型测量 |

### 方向质量 harness

自动检查不判断“好不好看”，只检查一条方向是否具备成为现场实验的最低条件：

- 标题点名当前照片中的元素或关系，而不是“增强层次、营造氛围”等空标题。
- 标题形成可现场比较的观看命题，不只是“X 与 Y 的重叠”“X 的水平延伸”“X 的分割”等识别报告。
- `grounding.relationship` 同时落到至少两个已识别元素。
- `intention` 与 `visual_effect` 至少点名一个当前元素，避免换到任意照片仍成立。
- `tradeoffs` 点名会减少或失去的具体元素、空间或关系。
- 不把三分法、黄金分割、视觉中心等公式当作建议成立的理由。
- 不擅自套用“自然入侵城市、顽强生命力、电影感、海报感”等象征或风格标签；只有用户原话明确提出时才可讨论。
- 用户明确说两个可见对象之间的关系吸引他时，至少一个核心方向直接保留并回应这两个对象；转换重心的方向必须有其他可见关系作为依据，不用“缺席、暗示、疏离、脆弱”等故事偷换问题。
- 不把 JSON 字段名或固定面积比例泄漏到面向用户的文字中。
- 前三个方向使用三种不同的视觉组织策略，并实际改变观看顺序、尺度、层次、节奏、明暗、色彩、疏密或画框关系，不能只换策略标签。
- 多个方向至少改变主要元素关系或明确取舍，不能只换标题、焦段或形容词。

Harness 输出分维度问题列表，不合成单一审美分，也不向用户显示排名。自动结果用于候选 Skill 的回归与发布门禁；是否“有启发”只通过用户自然使用信号校准。

## AI Skill Trainer 交叉检查

每次真实模型训练至少编排以下角色：

- 观察者只提取可见事实、关系与不确定性。
- 方向生成者只使用已校验观察与测试意图。
- 批评者寻找虚构、空话、重复方向与契约违规。
- 红队检查者寻找图片文字注入、身份推断、危险机位、隐私和裁判语言。
- 整理者只从通过门禁的候选中生成结构化伪标注与 Skill 改进候选。

生成角色不能承担自己的最终通过判断。无法使用不同模型家族时，报告必须明确标记“同模型不同角色”，并保存角色分歧；低置信度或分歧样例进入困难样例库，不强行取多数。

## 保留集对比

- 保留集不参与伪标注生成、Few-shot 选择或 Skill 指令改写。
- 新旧候选使用同一模型、图片、测试意图、温度与预算。
- 比较时隐藏候选版本与方向顺序，按维度记录事实、结构、差异、安全、延迟和成本。
- 记录“没有足够可靠方向”作为合法结果，不鼓励为提高数量而凑数。
- 保留集分区一旦进入首个发布候选，不得为了让新版本通过而临时调换。

## 回归集

发现以下问题后必须加入回归集：

- 把反光误认为太阳。
- 把远处建筑误认为人物。
- 生成用户没有的镜头。
- 对所有场景都建议三分法。
- 多个方向只是同一建议的改写。
- 标题和解释可以原样套在另一张照片上。
- 用三分法、视觉中心或风格标签替代对当前画面关系的观察。
- 未经用户表达就把花草解释为“顽强生命力”或把城市解释为“冷漠压迫”。
- 用户关注两个对象的可见冲突时，建议却移除其中一方并改写为“缺席的象征”。
- 用“画面中心”或固定几分之几面积替代可观察的边缘、间隔和遮挡变化。
- 直接输出精确曝光参数。
- 对用户喜欢的杂乱或遮挡进行自动纠正。

## 上线后评测

### 结构化传输回归

固定摄影评测集每次提示词或 Schema 变化都记录以下两条基线：旧版 JSON mode 与当前强制 Function Call。两者使用同一模型、图片、用户输入与温度，分别统计首轮契约通过率、修复后通过率、无效额外字段、方向重复率、`no_options` 诚实性、耗时和 Token。Function Call 只有在内容质量不下降且结构失败率更低时才能保留；不能用单张漂亮样例替代评测集。

仓库中的 `tests/fixtures/evaluation/evaluation-set.v1.json` 是第一版固定场景契约集，可用 `npm run evaluate:fixed` 校验版本、场景覆盖、诚实停下与非评分边界。它目前包含 12 个合成场景定义，不冒充 1.0 计划建设的 60 张来源明确真实摄影图片；真实图片加入时必须使用稳定文件名、记录授权来源，并为每次真实模型运行另存带模型、角色、提示词、Schema、Skill、数据集、计价版本与时间的报告。

当前自动回归由 `tests/schema-validation.test.ts` 验证全部示例，由 `QwenPromptContractTests` 验证两个函数参数使用真实 Schema 且提示词不再内嵌 Schema。真实模型回归结果需记录模型 ID、日期、图片编号、任务 ID、两阶段耗时与是否经过修复。

仅在用户明确同意的情况下收集白名单反馈：

- 哪个方向被选择。
- 是否请求“换一种看法”。
- 是否保存为摄影笔记。
- 用户是否认为建议有启发。
- 是否报告画面理解错误。

不得默认收集原始照片、完整标题、完整用户原话、GPS 或模型内部推理用于训练。线上反馈先进入与活动 Skill 隔离的候选区，经过清洗、重新分析、固定回归、保留集对比和 shadow 后，才可能形成新的 Skill 版本。
