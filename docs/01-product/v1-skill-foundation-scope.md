# 照见 1.0 Skill 基础版开发范围

状态：已确定范围，可进入开发计划
目标版本：`1.0.0-beta.1` → `1.0.0`
最后更新：2026-07-24

## 1. 版本定位

照见 1.0 不是在现有 MVP 上继续堆叠零散功能，而是把已经跑通的摄影闭环升级为可训练、可版本化、可回滚的垂直摄影 Agent：

```text
当前 MVP
固定提示词 + 两阶段分析 + 确定性参数工具

            ↓

照见 1.0
不可变产品原则
+ 可版本化摄影 Skill
+ 自动化 Skill 预训练与评测
+ 个人创作记忆
+ 受控的全局经验升级
+ 面向摄影复盘与后期思路的 CreativeIntent
```

`1.0.0-beta.1` 表示工程、Skill 和自动训练体系已经完整，可以进行受限公开测试。`1.0.0` 表示真实使用产生的自然反馈已经证明核心价值，并通过稳定版发布门槛。

商业化、多实例部署、支付和自动修图不属于本版本完成条件。

## 2. 核心目标

1. 保留现有“表达 → 观看可能 → 器材实现 → 摄影日记”闭环。
2. 把画面观察与观看方向从固定 Provider 提示词中抽离为供应商无关的 Skill。
3. 首批交付 `observe-scene` 和 `composition-relations` 两个基础 Skill。
4. 用来源明确的 60 张摄影图片建立第一版训练、回归和保留集。
5. 由多个模型角色完成批量分析、批评、红队和筛选，不建立人工逐图标注团队。
6. 建立候选 Skill 的评测、发布、启停和原子回滚能力。
7. 将用户个人偏好与全局 Skill 经验严格分离。
8. 建立 `CreativeIntent`，为摄影复盘和后期思路保留稳定数据接口。

## 3. 不可改变的产品原则

以下原则属于照见核心约束，不允许由训练数据、用户偏好或模型自动改写：

- 人负责感受、选择、取舍和按下快门。
- AI 提供观察、问题、可能性和解释，不宣布唯一答案。
- 不显示审美总分，不排名，不使用“最佳构图”“构图错误”“你必须”等裁判式表达。
- 不把三分法、黄金分割等公式当作正确性依据。
- 模型输出观察事实、创作意图和不确定性；焦段、曝光、ISO 与 ND 继续由确定性工具计算。
- 用户未允许改变的机位维度不得被模型假设为可移动。
- 不把人物身份、职业、关系、性格或内心故事当作图片事实。
- 用户图片、原话和使用记录默认不进入全局训练。
- 正式 Skill 不允许从线上数据直接热更新。
- 原图不被覆盖，后期能力必须可选择、可解释、可逆。

## 4. 术语与边界

### 4.1 核心原则

始终加载的产品宪法，包括人本摄影、隐私、技术计算与内容安全边界。

### 4.2 Skill

供应商无关的专项能力定义，包含触发条件、输入输出契约、工作流程、参考知识、Few-shot、反例、校验器和评测集引用。

本项目中的 Skill 是照见运行时能力模块，不等同于 Codex 的 `SKILL.md` 文件格式，也不绑定某一家模型供应商。

### 4.3 工具

产生确定性结果的程序能力，例如图片压缩、焦段换算、曝光计算、ND 换算、数据清理和可逆编辑预览。工具结果不由模型自由编造。

### 4.4 个人创作记忆

只属于当前账号、可查看、修改、删除和关闭的结构化偏好，例如用户经常保留的关系、常修改的建议和已经明确表达的创作倾向。

### 4.5 全局经验

经过授权、隔离、清洗、自动复核和回归验证后，才允许进入候选 Skill 的通用经验。单个用户的偏好不得直接升级为全局摄影规律。

### 4.6 AI Skill Trainer

离线运行的自动训练控制面，负责编排观察、方向生成、批评、红队、整理、评测和候选发布。它默认使用 Mock 验证流程；真实模型运行必须显式开启，固定 Provider、模型、计价版本和总预算，并在每次远端调用前取得费用租约。角色输出只保存脱敏结构化事实、方向、问题与候选，不保存原图、Base64、完整提示词或内部推理。训练结果继续停留在隔离候选区，不能直接修改活动 Skill。

## 5. 用户可见范围

### 5.1 保持现有核心体验

```text
选择摄影包
→ 拍摄或选择参考图
→ 说出什么吸引了我
→ 必要时回答一个澄清问题
→ 获得 2～5 个不排名观看方向，或诚实返回没有足够方案
→ 选择一种
→ 查看器材焦段与参数起点
→ 保存摄影日记
```

V1 Beta 不要求用户理解或手动选择底层 Skill。核心分析任务由服务端根据任务类型强制执行 `observe-scene → composition-relations`：模型只负责完成当前阶段，不能跳过、替换或自行选择核心 Skill。任务创建时固定两个 Skill 的版本与内容哈希，后台恢复时必须解析到完全相同的不可变制品；缺失或不匹配时停止本次云端分析并给出可重试错误，不静默切换到新版本。历史任务可显示本次使用的 Skill 和版本，便于解释与复现。

未来的可选风格、练习或辅助 Skill 可以由用户显式选择，或由运行时在获得授权后推荐；它们不能改变上述核心观察与构图关系链路，也不能把选择权交给模型自行决定。

### 5.2 个人创作记忆

用户可以：

- 查看照见已经记录的结构化偏好。
- 修改或删除错误偏好。
- 关闭新的个人偏好提取。
- 清空个人创作记忆而不删除摄影日记。
- 在账号导出中获得个人记忆与反馈记录。

个人创作记忆不得包含原始图片、完整用户原话、GPS、设备序列号或模型内部推理。

### 5.3 V1 不新增独立“构图课程”页面

`composition-relations` 在 V1 中首先作为现有现场观看流程的底层能力。独立专项练习、课程进度、A/B 取景练习和 Skill 目录属于 1.1 候选，不阻断 V1。

## 6. 基础 Skill 范围

### 6.1 `observe-scene`

职责：

- 提取具体可见元素。
- 记录遮挡、分离、延续、重复、方向、尺度、明暗、色彩、边缘和空间层次关系。
- 区分图片证据、用户补充与模型不确定性。
- 输出运动、动态范围和光线变化等技术观察。
- 在证据不足时降低置信度或明确无法确认。

不得：

- 输出构图方向。
- 推断身份、地点、人物关系或象征故事。
- 输出焦段、曝光、后期参数或审美判断。

首版输出继续兼容 `SceneUnderstanding` 的稳定语义，新增 Skill 版本快照而不是破坏现有业务契约。

### 6.2 `composition-relations`

职责：

- 只使用已经校验的画面理解与用户上下文。
- 在关键不确定性会改变取舍时提出一个具体澄清问题。
- 只在至少两种方向成立时提供 2～5 个方向。
- 每个方向点名至少两个画面元素及其关系。
- 每个方向只改变一个决定性视觉变量。
- 提出一个开放观看问题，不替用户回答。
- 给出 2～3 条“尝试动作 → 取景器可见变化”的现场试法。
- 解释保留、减少、视觉效果和取舍。

首版覆盖六种视觉组织策略：

- 遮挡与层次 `depth_occlusion`
- 尺度与环境 `scale_context`
- 节奏与线条 `rhythm_line`
- 明暗与色彩 `light_color`
- 疏密与留白 `negative_space`
- 画框与边缘 `frame_edge`

不得：

- 为达到数量要求改写标题或形容词凑数。
- 输出精确机位、实际焦段、光圈、快门、ISO、ND、白平衡、RAW、直方图或后期步骤。
- 把不同方向合成为审美评分。

## 7. Skill 通用契约

每个 Skill 至少具有以下版本化字段：

```text
skill_id
skill_version
status
description
trigger
input_schema_version
output_schema_version
instruction_version
reference_version
validator_version
evaluation_set_version
compatible_runtime
provider_requirements
content_hash
created_at
```

生命周期：

```text
draft
→ candidate
→ shadow
→ active
→ retired
```

要求：

- 同一时刻每个 Skill 只有一个活动版本。
- 历史分析永久保存当时使用的 Skill 版本，不随新版本重算。
- 未知主版本必须安全拒绝。
- 版本升级不得绕过 JSON Schema 和业务规则校验。
- 活动版本切换必须是原子的，并支持回滚到最近一个通过评测的版本。

## 8. 自动 Skill 预训练范围

本版本所说的“Skill 预训练”，是用固定摄影数据在离线流水线中生成、批评和筛选观察规则、参考知识、Few-shot、反例与校验规则，最终产物是一个新的 Skill 版本。它不修改基础大模型权重；LoRA、SFT、DPO 等模型微调不属于 1.0。

### 8.1 训练角色

每张训练图片依次或并行经过以下独立角色：

1. **观察者**：只提取可见事实、关系与不确定性。
2. **方向生成者**：基于已校验事实提出不同观看可能。
3. **批评者**：寻找无依据叙事、空话、重复方向和契约违规。
4. **红队检查者**：检查图片文字注入、身份推断、危险机位、裁判语言和敏感信息。
5. **整理者**：只从通过门禁的候选中生成结构化伪标注和 Skill 改进候选。

同一个模型角色不得同时给自己的输出作最终通过判断。若无法使用不同模型家族，必须记录“同模型不同角色”，不能冒充独立交叉验证。

### 8.2 自动标注定位

模型产生的训练标注统一标记为 `model-suggested`，不是人工事实或标准答案。每项保存：

```text
teacher_model
teacher_role
prompt_version
schema_version
evidence
confidence
critic_findings
red_team_findings
model_disagreement
validation_status
```

低置信度、模型意见冲突或无法通过确定性门禁的样例进入困难样例库，不强行取多数。

### 8.3 方向训练契约与历史证据

方向生成角色使用独立于公开 `SceneAnalysis 4.3` 的内部结构化契约。模型不直接撰写最终中文方向，而是提交：

- 已校验观察证据与画面元素；
- 六类视觉组织策略之一；
- 一个可见变量及其比较方式；
- 需要保留与可能弱化的元素；
- 当前允许的机位自由度；
- `options` 或显式 `no_options` 决定。

程序把结构化决定确定性投影为现有 `directions`，因此训练器升级不要求公开 API、历史任务或前端同步迁移。`no_options` 只能来自模型明确选择并通过业务规则校验，不能由过滤器根据“所有候选均失败”代为生成。

历史真实运行形成两类只读证据：

- 失败语料库只保存脱敏原因码、角色、样本、版本、来源运行哈希与可重放结构，不保存原图、完整提示词、内部推理或密钥。
- 暴露账本把任何曾进入 Mock 或真实运行选择范围的图片标记为已暴露，并区分是否产生过真实调用、是否被用于提示词或 Schema 改进。

已暴露图片仍可用于固定回归和历史比较，但不得继续宣称为“未见保留集”。需要验证泛化时必须建立来源许可明确、与历史来源和内容哈希不相交的新保留集版本。

### 8.3 不建立人工逐图标注团队

V1 离线训练不要求摄影师逐张标注或审核全部样例。事实、结构、差异、禁用内容与跨角色一致性由模型角色和确定性程序检查。

“是否真正有启发”不能由训练模型自证，也不在离线阶段伪装成自动事实；它在稳定版阶段通过用户自然使用中的选择、修改、拒绝和摄影日记反馈校准。

## 9. 第一版摄影数据集

### 9.1 规模与覆盖

统一采用 60 张来源明确的真实摄影图片：

| 类型 | 数量 | 主要覆盖 |
|---|---:|---|
| 风光与自然 | 25 | 层次、尺度、留白、光线、运动 |
| 城市与日常环境 | 15 | 线条、重复、边缘、遮挡、明暗 |
| 人物与环境人物 | 10 | 人物与空间、背景、尺度、光线关系 |
| 普通、模糊和困难照片 | 10 | 不确定、澄清、`no_options` 与失败边界 |

人物样例只训练可见姿态、位置、遮挡、尺度和光线关系，不训练身份识别、人物故事或摆姿裁判。

### 9.2 数据分区

| 分区 | 数量 | 用途 |
|---|---:|---|
| 训练集 | 36 | 生成伪标注、Few-shot 和 Skill 改进候选 |
| 回归集 | 12 | 固定检查已知失败，不随版本交换 |
| 保留集 | 12 | 新旧候选盲对比，不参与 Skill 生成 |

数据分区一旦进入首个发布候选，不得为了让新版本通过而临时调换。

### 9.3 最小来源清单

每张图片至少记录：

```text
asset_id
source_url
download_url
author
license
license_url
source_kind
allowed_usage
attribution
source_file_sha1
content_hash
downloaded_at
rights_verified_at
portrait_or_personal_data
privacy_review
derivative_path
dataset_split
status
```

第一版只使用自有、明确授权、公共领域、CC0 或经核验允许当前用途的开放许可图片。没有明确许可、需要绕过登录或付费限制、禁止自动访问或无法确认权利人的图片不进入训练。

训练图片和可能受许可限制的衍生物不提交 Git；仓库只保存清单、Schema、必要的合成 fixture 和不含图片内容的评测报告。

## 10. 自动评测与发布门禁

### 10.1 自动指标

V1 延续当前分维度指标：

| 指标 | Beta 目标 |
|---|---:|
| JSON 可解析率 | ≥ 99.5% |
| 严重虚构率 | < 3% |
| 意图响应率 | ≥ 90% |
| 方向差异率 | ≥ 85% |
| 画面落地率 | ≥ 95% |
| 澄清有效率 | ≥ 90% |
| 现场可执行率 | ≥ 95% |
| 器材可行率 | ≥ 95% |
| 裁判式语言率 | < 1% |

自动评测不得输出审美总分。每个失败必须保留维度、证据、Skill 版本和对应样例。

### 10.2 候选发布

```text
候选 Skill
→ Schema 与确定性门禁
→ 训练集报告
→ 固定回归
→ 保留集新旧对比
→ shadow
→ active
```

以下任一情况阻断发布：

- 未知或缺失数据来源。
- 新版本提高结构通过率但降低内容依据。
- 产生新的严重虚构、危险机位或隐私泄露。
- 方向重复、公式化或裁判式表达超过门槛。
- 无法回滚到最近一个有效版本。
- 真实模型运行没有记录模型、提示词、Schema、Skill、数据集、耗时与成本。

## 11. 个人记忆与全局进化

### 11.1 个人记忆

允许从以下明确行为提取结构化候选：

- 选择、修改或拒绝某个观看方向。
- 标记“值得试一次 / 太泛 / 画面依据不对”。
- 保存摄影日记。
- 在摄影日记中明确记录采用或拒绝原因。

点击顺序、停留时间、点赞量或单次保存不得直接被解释为稳定审美偏好。

### 11.2 全局候选隔离

```text
个人使用记录
→ 明确授权
→ 去标识化与字段白名单
→ 候选隔离区
→ 多模型重新分析
→ 确定性门禁
→ 回归集候选
→ 新 Skill 候选
```

V1 Beta 需要实现隔离、删除、导出和候选生成机制，但不要求已经积累足够数据形成首个全局自动升级。

任何全局升级都必须产生新 Skill 版本，不允许修改已有历史版本。

## 12. CreativeIntent 与后期铺垫

`CreativeIntent` 是拍摄前、拍摄中、摄影复盘和未来后期思路之间的共享语义对象，至少包括：

```text
subject_relations
attention_path
keep
reduce
framing_intent
tonal_intent
color_intent
motion_intent
depth_intent
texture_intent
uncertainties
tradeoffs
source_analysis_id
selected_interpretation_id
skill_versions
```

V1 范围：

- 定义并验证 `CreativeIntent` JSON Schema。
- 在用户选择观看方向后生成并保存快照。
- 关联分析任务和摄影日记。
- 支持导出和删除。
- 定义 `FinalPhotoObservation` 与 `PostProcessPlan` 的契约草案和示例。

V1 不实现：

- RAW 解码和管理。
- 自动应用曝光、曲线、HSL 或局部蒙版。
- Lightroom/XMP 导出。
- 生成式修图。
- 覆盖原图。

## 13. 工程与运行边界

- 继续使用 ASP.NET Core 10 + React/Vite。
- 继续通过 Provider Adapter 隔离具体模型。
- Beta 继续明确为 SQLite、进程内队列、内存额度和 SQLite Blob 的单实例部署。
- 真实 Skill 训练不进入默认 CI，不读取开发者密钥。
- 默认 CI 使用 Mock、Schema、fixture 和固定报告进行验证。
- 真实训练运行必须显式开启、设置预算并生成脱敏报告。
- 日志不得记录图片、Base64、用户原话、GPS、密钥、完整提示词候选或模型内部推理。

### 14.1 `1.0.0-beta.1`

- 自动训练流水线可用 Mock 完整运行，真实模型可显式运行并生成报告。
- 候选 Skill 在回归集和保留集上达到自动门槛。
- 个人记忆可查看、删除、关闭和导出。
- 全局候选隔离区不能直接修改活动 Skill。
- `CreativeIntent` 已保存到任务与摄影日记链路。
- 图片保留、账号删除、任务恢复、失败降级和预算开关通过回归。

### 14.2 `1.0.0`

在 Beta 条件之上，通过自然使用信号验证：

- 至少 30 名真实用户完成核心流程。
- 至少 60% 的用户认为产生了新的观看可能。
- 核心流程中位时间不超过 3 分钟。
- 没有严重隐私、错误参数或误导性建议问题。
- 存在重复使用、方向修改或摄影日记沉淀的证据。
- 已确认单次分析与离线训练的真实成本边界。

稳定版价值指标来自正常产品使用，不建立专门的人工逐图离线标注团队。

## 15. 明确排除

- 大规模全网无许可图片爬取。
- 用户数据直接写入正式 Skill。
- 无法回滚的线上自动进化。
- 模型权重微调、LoRA、SFT 或 DPO。
- 自动修图、滤镜、生成式改图和作品评分。
- 人像摆姿裁判或身份识别。
- Skill 商店与第三方 Skill 安装。
- 相机遥控、精确机位导航和实时逐帧分析。
- PostgreSQL、Redis、对象存储和分布式任务队列迁移。
- 支付、生产邮件、商店发布和完整商业运营。
