# MVP 范围

> 本文保留已经实现的 MVP 边界。下一阶段新增能力以[照见 1.0 Skill 基础版开发范围](v1-skill-foundation-scope.md)为准；1.0 不推翻本文中的人本摄影、隐私和确定性参数原则。

## MVP 目标

验证用户是否愿意在真实拍摄现场使用“表达 → 观看建议 → 器材实现”的闭环，并确认建议确实能打开新的观看可能。

## 必须具备

### 摄影包

- 创建一个器材档案。
- 登录后的摄影包归属于个人账号，并在个人中心的独立页面中查看、切换和删除；浏览器保留最近一次账号数据作为离线副本，但不再把设备级 `localStorage` 当作唯一数据源。
- 录入一台相机、最多三支镜头。
- 相机型号可从一份小型、带来源的内置起步目录中搜索选择，并始终允许手动输入；只有逐项核验的官方规格可自动带入计算，其他条目只匹配型号且要求用户确认传感器等字段。该目录只用于减少录入，不扩展为全量器材数据库。
- 支持手动录入传感器、焦段和最大光圈。
- 记录三脚架、ND 和 CPL 是否可用。

### 参考画面

- 使用手机拍摄或从相册选择一张图片。
- 原图只在浏览器本地解码：允许选择不超过 60 MiB、6000 万像素的 JPEG、PNG 或 WebP；常规分析图最长边压到 2048px、上传体积不超过 2 MiB，并通过重新编码移除 EXIF/GPS。服务端不持久化原图；为支持账号内重复查看，仅保存去元数据后的分析图，不承担常规二次压缩。
- 个人账号可注册、登录和退出；分析结果、任务明细与分析图只允许本人访问。一张分析图可以保留多次互不覆盖的分析结果，用户可以回到历史任务再次查看或删除。
- 选择后显示“原图尺寸/体积/画幅比例 → 分析图尺寸/体积/画幅比例”，并用确定性尺寸校验说明分析图是完整画面的等比缩放还是存在异常，不用肉眼猜测是否改变构图。
- 在浏览器本地读取可用的 EXIF 摘要，展示机身、镜头、焦距、光圈、快门、ISO、拍摄时间和是否包含 GPS；不显示精确坐标，也不把这些字段加入分析请求。截图、社交平台导出图或已清理图片可能没有 EXIF，应明确显示“未读取到”。
- 服务端只接受浏览器生成的 JPEG 分析图，并再次校验文件大小、文件头、完整 JPEG 尺寸、像素边界和请求字段；绕过前端限制的请求不得进入 Provider。
- 允许用一句话或快速选项说明“什么吸引了我”。
- 允许用户可选补充“画面里有什么、现场环境、想保留什么、愿意弱化什么、希望的感受与可改变的机位范围”，用于纠正图像误识别；不强制填写。
- 现场环境只传递用户明确输入的简短事实，例如光线变化、风、雾和地形限制；不上传 GPS、完整 EXIF，也不把本地展示的设备与曝光记录交给模型计算曝光。模型只能从分析图像素观察明暗、光向和反差，不能把画面观感冒充现场测光。

### 观看建议

- 先单独生成可核验的画面理解，再基于这份理解生成观看方向；画面观察与创作建议不能混成一次自由文本输出。
- 当识别不确定性会直接影响用户吸引点时，先追问一个与当前照片有关的关键问题，并允许用户选择候选答案或自行补充。
- 只在至少存在两种有充分画面依据且彼此不同的观看方向时返回 2～5 个方向；第 3～5 个方向只有存在新的具体画面关系或取舍时才保留。方向不按优劣排序，不得为了达到数量下限改写标题、焦段或形容词凑数。
- 无法形成至少两种可靠方向时返回“没有足够可靠的观看方案”，展示原因、已检查依据和可选下一步，不返回方向卡片；如果用户补充一个可见事实就可能解除关键不确定性，则优先追问而不是直接判定没有方案。
- 每个方向包含标题、意图、一个开放的观看问题、具体画面元素、元素关系、与用户吸引点的联系、保留、减少、建议视角、相对参考图的机位关系、取景器核对方法、2～3 条现场试法和解释。观看问题必须同时点名至少两个该方向的具体元素，只比较一个可见变量，不替用户回答。
- 现场试法必须同时说明“可以做什么”和“观察什么变化”，不得只是“突出主体、增强氛围”等抽象目标；不得超出用户声明的机位自由度，也不得编造精确位置、实际焦段、相机设置或曝光。实际焦段仍在用户选择方向后由参数引擎映射。
- 违规现场步骤只能由确定性逻辑替换为基于该方向具体元素的安全步骤，不得使用可套用到任意照片的固定通用句。
- 方向卡片优先使用 `suggested_crop` 在浏览器本地显示裁切并放大的取景预览。模型未给出取景框时，客户端依据该方向的 `view_width`、画幅方向和已有关注区域做确定性范围模拟，并明确标为“视角范围模拟”；方向详情同时显示预览效果和完整原图中的取景位置。两类预览都只模拟取景范围，不改变原图，也不模拟机位、透视、光线或最终成片。
- 不显示分数、排名或命令式移动指令。
- Mock 必须明确说明不识别上传图片，不得用固定样例冒充对当前图片的观察。
- 同一分析图与相同观察上下文的再次尝试，可短时复用已经通过校验的结构化画面理解；缓存不得包含图片、Base64、GPS 或密钥。用户修改想保留、愿意弱化或希望感受时重新生成方向；修改吸引点、画面内容、现场环境或澄清回答时必须重新识别。
- 允许用户在本机标记整次分析“有启发 / 太泛 / 识别不对”，并在方向详情标记“值得试一次 / 还不够具体 / 画面依据不对”。方向反馈只记录分析编号、方向编号、视觉策略和选择；两类反馈都不包含原图、Base64、GPS、用户文字或密钥，也不自动上传。

### 怎么拍

- 将等效视角转换为用户器材的实际焦段范围。
- 生成“稳妥手持”“低噪点/三脚架”“表达性拍摄”中的适用方案。
- 参数以范围、假设和调整逻辑呈现。

### 摄影笔记

- 保存参考图、用户意图、选中建议、器材和参数。
- 登录后的摄影笔记归属于个人账号，可在个人中心的“摄影日记”页面跨会话查看和删除。仅同步去元数据的缩略图与结构化笔记，不上传原图。
- 允许后续添加最终照片和个人感受。

### 个人中心

- 提供独立的个人中心总览，展示昵称、邮箱、加入时间，以及摄影包、摄影日记、分析任务数量。
- 允许本人修改昵称；邮箱在 MVP 中只读，后续需配合重新验证流程再开放修改。
- 从个人中心分别进入“摄影包”“摄影日记”“我的分析”，三个区域均只读取当前账号的数据。
- 用户 A 不得读取、修改、删除或通过资源编号推断用户 B 的摄影包和摄影日记。

## 可以延后

- 语音转文字可先使用系统能力；不自建实时语音服务。
- 焦段叠加框可在第二个迭代完成。
- 试拍 EXIF 校正可在纵向切片稳定后加入。

## 明确排除

- 实时逐帧 AI 分析。
- AI 自动控制相机。
- 复杂 AR 导航。
- AI 美学评分。
- 社区和内容推荐流。
- 生成式修图。

## MVP 退出条件

满足以下条件后才能讨论商业版：

- 完成不少于 30 名真实摄影用户测试。
- 至少 60% 用户认为建议提供了新的观看可能。
- 单次分析中严重虚构率低于 3%。
- 结构化输出可解析率达到 99.5%。
- 一次核心流程中位完成时间不超过 3 分钟。
- 已测得真实单次模型、存储与网络成本。
