# 完成定义（Definition of Done）

“代码写完”不等于功能完成。每项用户功能只有同时满足下列条件，才能标记完成。

## 单个功能

- 用户目标、非目标和异常路径已经写清楚。
- UI 有加载、空状态、错误、取消和重试状态。
- 新增数据有明确的保存位置、保留时间和删除方式。
- 核心逻辑具有自动化测试，边界值已覆盖。
- 埋点和日志不包含原图、精确位置、密钥或不必要的个人信息。
- 中文文案可理解，不把 AI 表达成审美裁判。
- 动态字体、屏幕阅读、颜色对比和触控区域经过检查。
- 在最低支持版本与至少一台真实设备上验证。
- 相关设计、API、数据模型或决策文档已经同步。
- 代码审查中的阻断问题已解决。

## AI 功能

- 响应通过 JSON Schema 校验，失败时有一次受控修复或清晰降级。
- 模型名、版本、提示词版本和评测集版本可追踪。
- 新版本在固定评测集上没有显著退化。
- 事实观察、审美解释和技术计算在数据结构中分离。
- 不直接把模型生成的曝光参数展示给用户。
- 超时、限流、内容安全拒绝和供应商不可用路径已验证。
- 画面理解、方向生成与可选修复各阶段的成本和延迟可观测，同时记录完整分析总耗时。

## Skill 与自动训练功能

- Skill ID、语义版本、内容哈希、输入输出契约、兼容运行时和评测集版本可追踪。
- 历史任务保存运行时 Skill 快照，不因活动版本变化而重算。
- 候选 Skill 经过 Schema、确定性门禁、固定回归、保留集对比和 shadow；发布失败不改变活动版本。
- candidate → shadow 和 shadow → active 分别绑定可复算内容哈希的阶段评测报告；报告覆盖九个非审美维度、冻结数据集 ID/版本/内容哈希、36/12/12 分区、严重失败、兼容性、成本与延迟，shadow 观察 ID 等于该独立候选运行的 ID。
- 活动版本切换是原子的，并已经演练停用和回滚。
- 每次状态变更记录 revision、操作者、原因、命令、前后状态以及适用的评测报告 ID/哈希；状态与审计在同一次原子写入中提交。
- 训练图片具有明确来源、许可、允许用途、内容哈希和固定分区；图片本体未进入 Git。
- 自动伪标注标记为 `model-suggested`，保存模型角色和分歧，不冒充人工事实。
- 生成角色不承担自己的最终通过判断；低置信度、角色冲突和硬门禁失败进入困难样例库。
- 真实模型训练必须显式开启并给出选择范围、Provider 调用次数上限和预算，不由默认 CI、普通测试或应用请求隐式触发。
- 每次真实训练调用都能追溯 Provider、模型、资产、角色、尝试、计价版本、Token、费用估算、延迟、失败原因和租约；预算不足或调用次数达到上限时停止新调用并保留完整终态报告。
- 线上反馈与活动 Skill 隔离，不能直接热更新正式版本。

## 个人创作记忆与后期铺垫

- 个人记忆只属于当前账号，并支持查看、修改、删除、关闭、全部清空和账号导出。
- 撤回同意后停止新反馈同步，切换账号和离线恢复不会串用偏好。
- 个人记忆和全局候选不保存原图、完整用户原话、GPS、设备序列号或模型内部推理。
- `CreativeIntent` 能追溯到分析、选中方向、Skill 版本和器材快照，并支持导出与删除。
- `FinalPhotoObservation` 与 `PostProcessPlan` 只定义可验证契约，不执行自动修图或覆盖原图。

## Harness 与回归

- Provider 首次调用、标准化、Schema/业务校验与可选修复的执行顺序由独立模块控制，HTTP 路由不得复制第二套策略。
- 可修复输出最多修复一次；不可修复错误不得被包装成盲目重试。
- 每次运行产生只含白名单元数据的轨迹，并通过自动测试证明不包含图片、Base64、用户原话、GPS、密钥或授权信息。
- `dotnet test Zhaojian.slnx` 在没有模型密钥和网络的情况下经过真实 ASP.NET Core 路由、图片防护、Provider、契约校验、幂等控制和用量计量；前端参数引擎继续由 Vitest 验证。
- 新增 Provider、契约版本或参数策略时，必须增加对应固定场景或边界断言。

## 参数功能

- 公式来源、单位和假设已记录。
- 所有输出经过器材范围校验。
- 不确定输入会显示区间或前提，而不是伪精确数字。
- 用户能看到“为什么是这个起点”以及如何根据试拍调整。
- 已知答案、边界值和异常输入测试全部通过。

## 候选发布版本

- 根工程、Web、参数引擎、.NET 程序和状态接口使用同一版本。
- `BetaReleaseEvidence` 记录每条命令的退出码、耗时和日志，发布压缩包具有 SHA-256。
- 预算耗尽、Skill 回滚、kill switch、账号删除/导出、图片留存、任务恢复和账号隔离已有自动测试或人工记录。
- 真实模型报告覆盖冻结 60 图、九个非审美维度、Provider/模型、提示词、Schema、Skill、数据集、计价、Token、成本、延迟、失败/不确定调用和隔离样例；最终保留 300 个成功角色结果、0 个失败/取消样例。
- 全量最多 15 个受控修复调用，其中最多 1 个无可信用量的上游调用按单次租约上界计费；每个失败或不确定尝试必须在同一检查点中由同资产、同角色、下一次成功尝试闭合，不能放宽未知枚举或删除失败记录。
- 3 图烟测、Mock 报告或手工 `passed` 字段不能使发布证据进入 `ready`。
- 单实例边界在 UI、状态接口、制品说明和已知限制中一致。
- 工程 Beta 与商店、备案、支付、真实设备和公开运营 Go/No-Go 分开，不用工程报告替代外部签字。
- 核心流程端到端测试通过。
- 无发布阻断级缺陷，其他已知问题有负责人和处理计划。
- 隐私政策、权限说明、客服入口、删除流程与实际实现一致。
- 模型和服务端具有限流、预算告警与故障降级。
- 付费版本完成沙盒购买、取消、恢复购买和失败返还验证。
- 应用商店素材不承诺无法证明的效果。
- 发布检查表已经由至少两次不同时间的检查完成。
- 有回滚或关闭云端分析的开关，不影响用户访问本地数据。
