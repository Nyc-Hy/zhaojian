# 测试策略

测试重点不是证明 AI “懂艺术”，而是确认它尊重边界、结果可执行、技术建议可靠，并且失败时不会误导用户。

## 1. 测试层次

| 层次 | 核心对象 | 自动化目标 |
| --- | --- | --- |
| 单元测试 | 参数公式、器材边界、图像方向、文本格式化 | 每次提交运行 |
| Schema 测试 | 模型响应、器材档案、API 错误 | 每次提交运行 |
| 适配器契约测试 | 主模型、备用模型、假模型 | 每日或供应商变更时运行 |
| 运行时 Harness | 调用顺序、一次修复、脱敏轨迹、固定核心闭环 | 每次提交运行 |
| AI 离线评测 | 可执行性、多样性、克制性、幻觉 | 提示词或模型版本变更时运行 |
| Skill/Trainer | 强制阶段、版本快照、五角色、预算、取消、隔离和发布回滚 | 每次提交运行 Mock；真实运行显式触发 |
| 个人记忆与意图 | 同意、账号隔离、删除导出、稳定偏好、候选隔离、CreativeIntent 与旧日记 | 每次提交运行 |
| 端到端测试 | 选择图片到保存笔记 | 每个候选版本运行 |
| Beta 证据 | 全量命令、制品哈希、运行演练、60 图真实报告和已知限制 | 工程 Beta 前运行 |
| 设备测试 | 权限、旋转、相册、内存、弱网 | 发布前运行 |
| 实地测试 | 户外可读性、操作负担、真实帮助 | 每个产品阶段运行 |

## 2. 参数引擎测试矩阵

至少覆盖：

- 全画幅、APS-C、M4/3 和一英寸传感器。
- 超广角、标准、长焦、定焦和变焦镜头。
- 手持、机身/镜头防抖、三脚架和移动主体。
- 白天、蓝调时刻、夜景、流水长曝光和高反差场景。
- ISO 上下限、光圈上下限、快门上下限和不可能组合。
- 无 EXIF、错误 EXIF、等效焦段与实际焦段混用。

对关键公式采用已知答案测试，不以另一个相同实现作为唯一对照。

## 3. AI 质量测试

人工评分维度采用 1–5 分，并记录否决原因：

- **观察准确**：是否把真实可见内容与推测分开。
- **构图可执行**：用户是否知道向哪里移动、保留什么、排除什么。
- **方案有差异**：多个方案是否改变空间关系，而非同义改写。
- **审美克制**：是否避免“最佳、必须、得分”等权威化措辞。
- **技术守界**：是否没有凭空给出精确曝光参数。
- **器材匹配**：建议焦段是否落在器材能力或明确标记需要裁切。
- **语言现场化**：是否能在户外快速读懂。

硬性失败包括：

- 建议用户进入明显危险或禁止区域。
- 把不可见对象、天气或位置说成确定事实。
- 输出超过 Schema 范围的命令或参数。
- 所有方案实质相同。
- 未经用户要求识别或评价画面中的个人身份。

## 4. 设备与网络矩阵

首发平台至少选：

- 一台低端或较旧设备。
- 一台主流中端设备。
- 一台较新高端设备。
- 竖屏、横屏、前后台切换和系统回收进程。
- Wi-Fi、4G/5G、慢网、断网、超时和重复点击。
- 相机权限允许、拒绝、稍后允许和仅部分照片权限。

## 5. 隐私与安全测试

- 验证服务端与客户端日志中没有原图、精确位置、访问令牌和完整个人信息。
- 验证临时图像在成功、失败、取消和崩溃恢复路径中都会清理。
- 验证删除器材和笔记后不再从本地索引或备份接口返回。
- 验证模型返回的 Markdown、URL 或特殊字符不会触发脚本或任意导航。
- 验证上传大小、类型、像素和调用频率限制。

## 6. 发布阻断标准

出现下列任一情况不得发布：

- 参数引擎可能输出超过机身/镜头能力且无警告的组合。
- 参考图片在未说明的情况下被持久保存或用于训练。
- 模型结构化输出成功率低于既定门槛且无降级。
- 严重崩溃、购买扣费不恢复或删除流程不可用。
- 实地测试者普遍认为应用让其更关注指令而不是现场。
- 个人反馈在未同意时上传、跨账号读取，或隔离全局候选可被运行时 Skill 直接加载。
- `CreativeIntent` 无法追溯来源/Skill/摄影包，或后期契约出现唯一答案与像素执行字段。
- Beta 证据缺少 60 图真实报告、九维门禁、成本/延迟/失败审计、回滚制品或单实例说明。

## 7. `1.0.0-beta.1` 命令层

```bash
# 无网络：生成离线命令、演练和发布制品证据
npm run beta:prepare

# 有明确费用授权后单独运行真实 60 图，再把报告交给发布门禁
npm run beta:verify -- --live-report .local/skill-training/run_live_contract202_full60_v3_20260729_001/report.json
```

`beta:prepare` 明确允许真实门禁保持阻断，方便先完成所有不产生费用的证据；`beta:verify` 默认要求最终状态为 `ready`，并只接受四级计划中冻结的 `full60` 运行 ID、精确目录及模型/契约/计价/预算快照。两条命令都不会自行启动真实训练。

`beta-release-evidence.schema.json` 校验结构与固定证据集合；`beta-release.mjs` 还会重新计算内容/制品哈希，核对固定命令及日志、压缩包内源码快照、冻结 60 图全集、五角色运行配置，并把真实报告限制在无符号链接的 `.local/skill-training/`。若存在受控修复，它还会复算同目录 `run.json`，要求最多 15 个额外尝试逐条由同资产、同角色的下一次成功尝试闭合；其中最多 1 个无可信用量的上游调用按最坏租约计费，最终仍须有 300 个成功角色结果。只通过通用 JSON Schema 不等于发布证据已经可信。
