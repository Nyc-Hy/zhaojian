# 产品与开发路线图

最后更新：2026-07-28

路线图按验证门槛推进，不以堆功能作为完成标准。当前 MVP 纵向闭环、ASP.NET Core 后端、个人账号、任务历史与确定性参数引擎已经形成；下一阶段进入“照见 1.0 Skill 基础版”。

完整范围见[照见 1.0 Skill 基础版开发范围](../01-product/v1-skill-foundation-scope.md)，逐工作包计划见[照见 1.0 Skill 基础版开发计划](v1-skill-foundation-plan.md)。

## 当前基线：MVP 已跑通

已具备：

- “表达 → 观看可能 → 器材实现 → 摄影日记”核心闭环。
- `SceneUnderstanding` 与 `SceneAnalysis` 两阶段结构化契约。
- Mock/Qwen Provider 隔离、一次受控修复与固定评测。
- ASP.NET Core Identity、异步任务、账号历史与图片最小化保存。
- 焦段、快门、曝光和 ND 的确定性参数引擎。
- 12 个不含真实图片的合成固定场景。

进入 1.0 开发前，先把当前大量迁移改动复核、验证并形成清晰的 MVP 基线提交。

## 阶段 0：冻结 MVP 基线

目标：建立可回退、可比较的工程起点。

交付：

- 完整工程验证、固定评测和 Klari 刷新结果。
- 当前架构、单实例部署边界和已知问题记录。
- 独立的 MVP 基线提交。

出口条件：

- `npm run verify` 与 `npm run evaluate:fixed` 通过。
- 迁移改动与后续 Skill 改动能够在 Git 历史中清楚区分。

## 阶段 1：Skill 契约与运行时

目标：把专项摄影能力从固定提示词升级为供应商无关的版本化模块。

交付：

- `SkillDefinition`、训练数据、训练报告与 `CreativeIntent` 契约。
- Skill 注册表、生命周期、内容哈希、活动版本指针与历史快照。
- 候选切换、停用和原子回滚能力。

出口条件：

- 未知主版本、哈希不匹配和运行时不兼容时安全失败。
- 历史任务不随活动 Skill 更新而重算。

## 阶段 2：两个基础 Skill

目标：完成第一批可复用专项摄影能力。

交付：

- `observe-scene`：提取可见元素、关系与不确定性。
- `composition-relations`：基于已校验观察提供 2～5 个不排名观看方向，或诚实返回 `no_options`。
- 六类视觉组织策略、反例、固定 fixture 与内容边界测试。

出口条件：

- 现有 HTTP 契约与用户核心流程不退化。
- Provider 与 HTTP 路由不再保存 Skill 专属提示词。
- 两个 Skill 均可在 Mock 环境独立验证。

## 阶段 3：数据集与 AI Skill Trainer

目标：用小而结构化的数据集建立可重复的自动预训练能力。

交付：

- 60 张来源明确真实照片的清单与 36/12/12 固定分区。
- 观察者、方向生成者、批评者、红队检查者和整理者流水线。
- `model-suggested` 伪标注、困难样例库、分歧记录与预算控制。
- Mock 训练命令与显式开启的真实模型训练命令。

出口条件：

- 图片来源、许可、哈希、人物信息标记和分区完整。
- 同一模型角色不能给自己的输出作最终通过判断。
- 真实模型训练不会由默认 CI 或普通测试意外触发。

## 阶段 4：评测、发布与回滚

目标：让 Skill 升级成为可审计的软件发布，而不是直接改提示词。

交付：

- Schema、业务规则、内容安全和多维质量报告。
- 固定回归与保留集新旧版本对比。
- `candidate → shadow → active → retired` 发布流程。
- 活动版本切换、kill switch 与回滚演练。

出口条件：

- 发布失败不会改变活动 Skill。
- 回滚后新任务立即使用旧版本，历史任务保持原快照。
- 不生成或展示单一审美总分。

## 阶段 5：个人创作记忆与后期语义铺垫

目标：允许照见理解个人创作倾向，同时为未来摄影复盘和后期思路建立接口。

交付：

- 可查看、修改、删除、关闭和导出的个人创作记忆。
- 与全局 Skill 经验物理隔离的候选反馈区。
- 可追溯的 `CreativeIntent`。
- `FinalPhotoObservation` 与 `PostProcessPlan` 契约草案。

出口条件：

- 个人偏好默认只影响当前账号。
- 原图、完整用户原话、GPS 和模型内部推理不进入个人记忆或全局候选。
- 本阶段不执行自动修图或不可逆像素修改。

状态（2026-07-28）：已完成。个人反馈默认关闭并按账号隔离，明确同意后只同步枚举白名单；不同任务的重复信号才能形成可编辑偏好，全局候选没有运行时读取入口。`CreativeIntent` 已接入分析任务、摄影日记、历史、导出和删除，后期能力仍停留在可逆多方案契约。

## 阶段 6：`1.0.0-beta.1` 收口

目标：交付可以受限公开测试的第一个大版本。

出口条件：

- 两个基础 Skill、训练流水线、发布回滚和个人记忆完整可用。
- 60 图数据集和自动评测报告可复现。
- 核心流程、旧任务、账号隔离、删除导出和离线恢复通过测试。
- 无高严重度隐私、安全、契约或参数错误。
- 已知限制、模型成本和单实例部署边界被明确公开。

状态（2026-07-28）：离线工程门禁、Beta 证据契约、统一版本、发布制品、预算/回滚/kill switch/数据生命周期演练和真实浏览器闭环已经完成。工程证据仍由“60 图真实模型报告”一项阻断；3 图烟测与 Mock 报告不会被用来替代该门槛。商店、备案、支付和真实设备矩阵继续属于公开发布检查，不阻断工程实现但阻断公开 Go-Live。

## 稳定版：`1.0.0`

Beta 之后只使用真实产品中的自然行为信号校准价值，不建立摄影师逐图离线标注团队：

- 哪个方向被选择、修改或拒绝。
- 是否请求换一种看法。
- 是否保存为摄影日记。
- 用户主动提交的枚举反馈。

稳定版要求上述信号达到预先冻结的阈值，且没有隐私、成本或安全门槛退化。自然反馈只用于生成隔离候选，不能直接更新活动 Skill。
