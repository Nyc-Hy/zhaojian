# 摄影参数引擎

## 目标

参数引擎把用户选择的表达、器材能力、现场约束和真实测光转换为可解释的拍摄起点。它必须是确定性、可测试的程序，不依赖语言模型计算曝光。

## 输入

### 器材

- 传感器宽高或裁切系数。
- 实际焦段范围。
- 最大/最小光圈。
- 机身与镜头防抖能力。
- ISO 范围和用户最高可接受 ISO。
- 快门范围。
- 三脚架、ND、CPL 和快门线。

### 创作选择

- 目标等效视角或视角类别。
- 景深优先、冻结运动、表现运动或低噪点。
- 手持或三脚架。
- 是否接受运动模糊。

### 现场信息

- 相机测光结果或试拍 EXIF。
- 高光风险。
- 可见运动强度。
- 预计光线变化。

手机参考图只可提供风险提示，不能作为精密 EV 测量的唯一来源。

## 焦段与视角

水平视角：

```text
horizontal_fov = 2 × atan(sensor_width / (2 × focal_length))
```

近似等效焦段：

```text
equivalent_focal = actual_focal × crop_factor
actual_focal = equivalent_focal / crop_factor
```

注意：

- 裁切系数用于视角换算，不改变实际曝光光圈。
- 透视关系主要由拍摄位置决定，不由焦段单独决定。
- App 只能显示视角近似框，不模拟真实镜头的景深、焦外、眩光与畸变。

## 曝光关系

在 ISO 100 下：

```text
EV100 = log2(N² / t)
```

其中：

- `N` 为光圈值。
- `t` 为快门秒数。

已知现场 `EV100`、目标光圈和快门时，可计算起始 ISO：

```text
ISO = 100 × N² / (t × 2^EV100)
```

所有结果必须经过相机支持范围、用户偏好与步进值取整。

## 手持安全快门

基础规则不是硬编码“1/焦距”，而是：

```text
minimum_shutter ≈ 1 / (focal_length × crop_factor × stability_factor)
```

`stability_factor` 根据：

- 用户稳定能力。
- 像素密度。
- 是否需要大尺寸输出。
- 机身/镜头防抖。
- 拍摄姿势与场景运动。

防抖只补偿相机抖动，不补偿树叶、人、车辆和水流运动。标称防抖档数不能无条件全额使用，默认采用保守折减，并允许用户通过历史试拍校准。

## ND 换算

保持光圈和 ISO 时：

```text
new_shutter = base_shutter × 2^nd_stops
```

引擎必须区分 ND 标识方式，如 ND8、ND64 与 3 档、6 档，并在 UI 中统一显示档数和倍数。

## 景深辅助

MVP 只提供保守光圈范围和对焦区域说明，不强制使用超焦距。后续若实现景深计算：

```text
hyperfocal = f² / (N × c) + f
```

必须明确弥散圈、输出尺寸和观看距离假设，避免把理论值当作绝对清晰边界。

## 输出方案

根据场景返回 1～3 个适用方案，不强行填满：

### 稳妥手持

- 先满足相机抖动和场景运动的快门下限。
- 光圈满足基本景深。
- ISO 在用户上限内自动补足。

### 安静画质

- 三脚架可用时优先基础 ISO。
- 光圈在画质与景深平衡范围。
- 快门由实际测光决定。

### 保留运动

- 先确定目标快门区间。
- 计算 ISO、光圈和 ND 需求。
- 明确哪些元素可能一起模糊。

## 试拍校正

若导入真实相机照片：

1. 读取光圈、快门、ISO、焦段和曝光补偿。
2. 检查高光、阴影、抖动与运动效果。
3. 计算需要调整的 EV。
4. 根据当前创作优先级只调整最合适的变量。
5. 解释调整会带来的副作用。

## 安全规则

- 不在缺少测光依据时输出单一“正确曝光”。
- 不推荐器材不支持的焦段、光圈和快门。
- 不把更低 ISO 永远视为更好。
- 不把 F16/F22 默认当作“全清晰”方案；需要提示衍射与长曝光影响。
- 不把防抖能力用于补偿主体运动。
- 所有结果保留原始计算值和 UI 取整值，便于测试。
