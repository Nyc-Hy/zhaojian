# 隐私与安全

## 隐私目标

参考图是用户观看过程的一部分，可能包含路人、住宅、位置和相机信息。默认策略应当是：少上传、少保存、少关联、可删除。

## 数据分类

### 高敏感

- 原始照片与参考图。
- 精确 GPS。
- 人脸和住宅内部画面。
- 相机序列号。
- 用户自由表达文字。

### 中敏感

- 摄影包型号。
- 模型分析结果。
- 粗略拍摄时间和地点。
- 使用与付费记录。

### 低敏感

- 匿名性能指标。
- 无内容的错误码与延迟。

## 默认处理

移动端上传前：

- 生成压缩副本。
- 仅在设备内解析原图的必要 EXIF 摘要用于用户核对；精确 GPS 坐标不进入界面状态、日志或请求，只显示是否检测到定位字段。
- 把分析图限制为最长边 2048px、JPEG 不超过 2 MiB；超限时在设备上继续降采样或降低质量。
- 移除 GPS。
- 移除相机序列号和不必要 EXIF。
- 保留方向信息，或在像素旋转后删除方向标签。
- 告知用户图片将发送到云端模型。
- 对比解码后原图与分析图的长宽比；只有在像素取整误差范围内一致时显示“完整画面等比缩放、未裁切”。

服务端：

- 不进行常规二次压缩；验证分析图后交给 Provider，并将去元数据的分析图按账号保存，用于本人重复查看历史结果。
- 即使 MIME 声明正确，也检查 JPEG 文件头、结束标记、尺寸与像素边界；2 MiB 以上文件在进入模型前拒绝。
- 账号密码交给 ASP.NET Core Identity 处理；会话 Cookie 设置 HttpOnly、SameSite 和安全策略，所有有副作用的 Cookie 请求验证 CSRF Token。
- 分析任务和参考图查询必须同时满足登录策略与资源所有权，不允许仅凭任务 ID 或图片 ID 访问。
- 服务端只保存重新编码后的分析图，不保存原图或 EXIF/GPS；用户删除最后一个关联任务时删除对应分析图。默认到期 30 天后清除分析图字节，保留结构化结果，并在历史页明确标记图片不可用。
- 日记缩略图必须通过完整 JPEG 解码、1024px 边长和总像素校验；账号同时受日记数量与缩略图总字节额度约束。
- 图片使用随机对象键，不使用用户输入作为文件名。
- 采用传输加密和静态加密。
- 用户删除图片关联的最后一条任务时立即删除；自动保留期限在正式上线前定案并实现。
- 日志不记录图片 URL、Base64 和自由文本。
- 密码恢复码默认不进入 HTTP 响应；只有显式开启的本机开发演示、loopback 请求和未配置邮件发送器同时满足时才允许返回。
- 模型供应商的数据使用条款必须纳入上线审查。

离线 Skill 训练：

- 只读取来源、许可和分区已通过门禁的数据集；训练运行与制品默认写入 Git 忽略目录。
- Mock 不读取图片，Mock 制品由契约强制标记为不可用于正式训练。
- 运行检查点、样例制品和报告使用字段白名单，并额外拒绝图片、Base64、GPS、完整用户文字、内部推理和审美总分字段及其命名变体。
- 低置信度、角色分歧和红队阻断保留最小必要证据并进入隔离区，不把模型多数意见升级为事实。
- 真实训练必须显式声明联网、Provider、模型、计价版本、生效时间、Token 单价、单次调用租约上限、Provider 调用次数上限和正预算；小样本烟测还应显式列出来自正式清单的资产 ID，默认 CI 与普通测试只使用无网络 Fixture。
- 真实角色结果只持久化 Schema 白名单字段和用量，不写原图、Base64、完整提示词、授权头、模型内部推理、GPS 或审美总分。
- 角色结果在 Provider 归一化和文件写入两层拒绝邮箱、电话号码、精确地址与凭据样式文本；命中后按无效输出重试或隔离，不落盘。
- 中断中的费用租约在恢复时按最大单次费用保守结算；预算不足或调用次数达到显式上限时停止新调用，但不得删除已生成的角色结果或省略未处理样例。
- 离线评测报告只允许版本、哈希、分维度数值、门禁和最小失败证据等 Schema 白名单字段；读取与发布时都拒绝图片、Base64、完整用户文字、GPS、内部推理、审美总分、符号链接越界、超大文件和敏感文本模式。
- 发布命令不接受任意“已通过”布尔值；必须重新核验评测报告路径、内容哈希、Skill 目标、阶段和完整门禁。报告篡改或审计写入失败时，活动版本保持不变。
- 评测报告和注册表状态是本机维护控制面的制品，不是对恶意系统管理员的密码学证明；`.local/skill-evaluations/`、Skill 资源与 `App_Data/skill-registry-state.json` 只授予受信维护账号写权限。应用用户和远程 API 均无发布写入口。

个人创作记忆与全局候选：

- 个人记忆和反馈同步默认关闭，分别由两个开关控制；只有明确同意后才接受当前账号设备队列的白名单枚举反馈。
- 服务端重新验证任务所有权、方向 ID、视觉策略和任务 Skill 快照，拒绝客户端拼装 Skill 内容或跨账号引用。
- 不采集停留时长，不把单次点击解释为稳定偏好；至少两个不同分析任务的明确反馈才会形成结构化偏好。
- `FeedbackRecord`、`CreativePreferenceRecord` 与设置保留 `user_id`；全局候选不保留 `user_id`，但通过受控外键与源反馈保持可删除性。
- 全局候选不提供应用 API 或运行时读取入口，不能修改活动 Skill。任何后续升级必须形成新版本并重新经过固定回归、保留集和 shadow。
- 删除反馈同步删除对应候选并重建偏好；清空个人记忆不删除日记；注销账号级联删除设置、反馈、偏好、创作意图和其候选。
- 账号导出包含结构化设置、反馈、偏好、隔离候选摘要和 `CreativeIntent`，不包含模型内部推理或活动 Skill 正文。

创作意图与后期契约：

- `CreativeIntent` 只从本人已经校验的任务、方向和服务端快照生成，客户端不能提交自由结构覆盖来源。
- 删除来源分析后保留契约内最小来源 ID、Skill 和摄影包快照；删除意图时日记关联置空。
- `FinalPhotoObservation` 和 `PostProcessPlan` 不接收或执行 RAW、曲线、HSL、蒙版、像素坐标或生成式修改；多个可逆思路不构成唯一正确答案。
- Beta 发布证据只复制真实训练报告的白名单摘要与文件哈希，不复制图片、角色原文、完整提示词或推理。

## 用户控制

- 可以不创建账户使用本地能力。
- 可以删除单次分析任务；图片没有其他任务引用时同步删除云端分析图。
- 个人数据导出和账号整体删除已经提供应用内入口；正式上线前仍需复核备份、对象存储和外部工单中的同步删除时限。
- 可以独立关闭个人记忆、撤回反馈同步、停用/删除单条偏好、删除反馈或清空个人记忆；这些操作不要求删除摄影日记。
- 可以保存、导出和删除 `CreativeIntent`；旧日记或已删除意图的日记仍可读取。
- 是否参与质量评测必须明确选择。
- “不用于训练”必须是实际技术和合同能力，而不是只有文案。

## API 密钥

- 只存在服务端秘密管理系统。
- 不写入仓库、移动端资源或崩溃日志。
- 按环境和供应商分离。
- 设置调用限额、预算告警和密钥轮换。

## 内容与安全

虽然产品聚焦风景，仍可能接收到包含人物、儿童、事故或私人场所的图片。需要：

- 最小必要的内容安全检查。
- 不对可识别个人做身份推断。
- 不输出住址、身份、健康、民族等敏感推断。
- 发现明显私人场景时提示用户谨慎上传，而非进行详细分析。

## 威胁模型重点

- 移动端密钥提取。
- 恶意超大图和解码攻击。
- Prompt injection 藏在图片文字中。
- 模型输出绕过 Schema。
- 越权读取他人分析结果。
- 云存储生命周期失效。
- 成本型滥用和机器人刷调用。

## 上线前必须完成

- 数据流图与第三方清单。
- 隐私政策。
- App Store 隐私标签核对。
- 删除流程实测。
- 供应商数据保留设置核对。
- 服务端预算、限流和告警。
- ASP.NET Core 请求体限制、请求超时、客户端/IP 限流、模型并发保护和 CORS 白名单经过集成测试。
- 60 图真实模型报告、Beta 发布证据、kill switch、Skill 回滚、预算耗尽和账号数据生命周期演练归档。
